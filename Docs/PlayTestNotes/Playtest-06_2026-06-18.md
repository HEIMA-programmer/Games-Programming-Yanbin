# Playtest 06 — 2026-06-18 (ship-build validation)

**Build / version:** v1.1.2 — the submission build (v1.1.1 gameplay; v1.1.2 adds only the
post-audit dead-code / documentation cleanup, with no gameplay change). Run from the
**standalone Windows build** (`Aftertrace.exe`, the artifact that ships), with an in-editor
cross-check.
**Levels tested:** full flow — MainMenu → Cut_00 → Level_00 → Cut_01 → Level_01 → Cut_02 →
Level_02 → Cut_03 → MainMenu, plus Level Select replays.
**Tester:** self (developer). This is the final ship-build **validation run** — not a
discovery round: it re-tests every prior open item on the build that will actually be
submitted, and adds the content that did not exist at [Playtest 05](Playtest-05_2026-06-11.md)
— Level 1's S3 freight minefield and S4 three-lock finale (v1.1.0, PR #155) and the
event-driven stun-coaching beat (v1.1.1, PR #156). The full run doubles as the take recorded
for the demo video.
**Setup:** standalone Windows player, 1920×1080, keyboard.

## Goal of this round

Playtest 05 validated v1.0.0; three things changed afterwards and had only per-session
developer verification (DevLog [Session 11 §5](../DevLog/Session-11_2026-06-12.md)) until
now. This round closes that gap on the build that ships:

1. **Does Level 1's expanded back half hold up?** The S3 freight minefield (two chained
   crates pushed through mass-keyed mines) and the S4 three-lock finale (a latching gate
   that needs crate + echo + player on three plates at once) are the most complex puzzle
   content in the game and had never had a full-run validation.
2. **Is Playtest 05's one residual gone?** The silent Level 2 exit door must now be audible
   on the shipped scene.
3. **Do the v1.1.x rule changes behave?** Story-freeze freezing the whole world (including
   drone stun timers), and the decoy-stun coaching beat firing on the first *proven* stun.
4. **Does the standalone build itself run clean?** Art, fonts, audio, no missing-sprite
   magenta, no console errors, working quit — the things only a real build, not the editor,
   can confirm.

## Tasks performed

1. Built the standalone Windows player and launched `Aftertrace.exe` from a clean folder
   (no Unity, no project) — confirmed it starts at the main menu.
2. Full run, menu to the Act 4 closing and back to the menu, letting every cutscene and
   music transition play out.
3. Level 1 S3: pushed the two-crate train through the mine lane from both sides; confirmed
   the mines arm / blink / detonate on the player but never on the crates.
4. Level 1 S4: solved the three-lock finale — staged a crate on one plate, recorded an echo
   onto the second, stood on the third, confirmed the gate latches only with all three held
   in the same instant, and paced the run against the sprint mine.
5. Level 2: triggered a decoy-stun and confirmed the "rub eyes" beat fires exactly once, on
   the first stun (not at a corridor position), and that the stun countdown pauses for the
   beat so the escape window survives.
6. Listened to every exit door, with attention to the Level 2 → Cut_03 door (Playtest 05's
   residual defect).
7. Skip-abuse: Esc through every act, including during a music transition's silence gap
   (the case that leaked before v1.0.0).
8. Exploit re-test: wall-hug + jump on every vertical face; the L2 segment-5 sentinel
   jump-over from every approach ledge.
9. Level Select: entered each level directly, finished, confirmed the return paths; confirmed
   no Level 3 entry anywhere; confirmed Act 4 sets the completion flag and the menu shows its
   completed state.
10. Build hygiene: watched the first frame of every scene load; checked for missing-sprite
    magenta; confirmed every font renders with no boxes; quit from the menu cleanly.
