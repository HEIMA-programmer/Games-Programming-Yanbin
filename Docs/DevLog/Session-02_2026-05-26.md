## 3. Decisions & how my thinking changed

- **Decision:** Make the cone a **real LoS test** — range + half-angle + an `unobstructed`
  Ground-layer raycast, not a trigger volume.
  **Why:** A trigger volume "sees" through walls, which kills the whole point of cover. The
  raycast against `sightBlockMask` is what lets a cover pillar or a closed door break sight.
  **Alternatives considered:** keep the cone as a trigger and ignore-list specific
  colliders — rejected as fragile and not what the player would expect.

- **Decision:** **Clone-first** target acquisition (`AcquireTarget` checks the active clone
  before the player), and **chase speed `6` < player `7.5`** with a per-drone leash.
  **Why:** This is what makes the echo's "decoy" verb meaningful. If chase >= player, the
  player can never escape; if the drone can see both equally, the clone competes with you for
  attention rather than relieving it. Decoy first, escape always possible, never cornered.
  **Alternatives considered:** clone is "priority unless within X units of the player." Felt
  like a fudge — clone-first is the rule players can actually predict from the fiction.

- **Decision:** Stealth detection is **opt-in per drone**, not a global rule. Only the L3
  corridor drones run with `detects: true`.
  **Why:** L2 was designed around contact-only drones; turning the whole game into stealth-
  on-sight would break the L2 puzzles I already validated in Session 1. Making it a
  per-drone flag means L3 introduces the rule and L2 stays consistent with how it taught the
  enemy in the first place.

- **Decision:** Tear out the L3 mirror room's puzzle and replace it with a small
  optional **Echo-Lift**.
  **Why:** Two compounding problems — the room's one-way gate could lock permanently (a
  hard softlock if you tried to backtrack), and the door it gated was redundant because the
  ground beneath it was already open. The honest fix wasn't "patch the door"; it was
  "remove the puzzle that needed it." The replacement is a single readable verb
  (record → ride → jump) for an optional fragment, which is closer to what the area was
  supposed to teach anyway.

- **Decision:** Death juice is **hit-stop + shake**, both short, both on unscaled time.
  **Why:** Big juice on death feels great once and tedious by the tenth respawn. ~90ms
  hit-stop + a 0.55-amplitude shake reads as "you got hit" without dragging out the retry loop.
  Running on unscaled time means the shake doesn't freeze with the timescale.
  **Alternatives considered:** longer hit-stop, slow-motion respawn, vignette flash. Cut as
  too heavy for a game where respawns are a learning step, not a punishment.

- **Decision:** Generate the TMP font asset from the committed `.ttf` in a build step,
  rather than checking in a hand-made asset.
  **Why:** Keeps the **one-click reproducibility** story — the project should still build
  from the `.ttf` alone if the `.asset` is deleted. The fallback to TMP default if the
  `.ttf` is missing keeps the build resilient.

- **Decision (correction added during this session):** Several Session-1 "polish" TODOs were
  already done.
  **Why:** Re-reading the Session 01 plan I found the echo trail (TrailRenderer on Echo),
  landing dust (`PlayerAnimator.OnLanded`), and the hard-landing shake (`CameraShake`
  subscribing to `Landed`) were already in the MVP. Logged a correction in Session 01 §6
  rather than re-implementing them. Honest > complete-looking.

- **Decision (PR #144):** Rename to **Aftertrace** for the player-facing title, but keep
  the C# namespace `EchoShift` and the `EchoShift ▸ Build All` editor menu as-is.
  **Why:** "Echo Shift" was a working title — only the "Echo" half was actually expressed
  in the slice (the "Shift" mechanic is still a Milestone-2 spike, not committed). "Aftertrace"
  reads more like the game's actual subject (a machine retracing its own past), and is
  unique enough to search for. The namespace, the editor menu, and the in-fiction word "echo"
  stay because they are *code identifiers* / *fiction*, not the title — renaming them
  would churn every script and every scene's `m_Script` GUIDs for zero shipping benefit.
  **Alternatives considered:** rename everything (including the namespace); leave the
  working title in place. Rejected as either churn-for-its-own-sake or commitment to a
  name the game wasn't really living up to.

- **Decision (PR #144):** Write the planning artefacts (`ROADMAP.md` + `BACKLOG.md`) into
  the repo *now*, mid-project, rather than at the end.
  **Why:** The module rewards visible process. A roadmap that exists during development
  and a backlog the GitHub board mirrors gives the markers something to check against the
  PRs as they land, instead of a retrofitted plan written after the fact. The §1 "Done"
  entries in the backlog double as a written acceptance record for PRs #1–#7.

## 4. Problems hit & how I solved them

- **Drone could chase off the level / corner the player against a wall.**
  *Cause:* nothing bounded the chase target. Once aggro'd, the drone followed the player's X
  forever, including past the ledge it patrolled on.
  *Fix:* per-drone `leash` (default 5 units past `patrolDistance`). `Chase` and `Search`
  clamp position to `[origin.x − bound, origin.x + bound]`; if the drone hits the bound it
  enters `Return` instead. L2's upper-gauntlet drone uses a tighter `leash: 4` so it can't
  chase off the high ledge. (PR #5, [PatrolDrone.cs:171–183 as of PR #5](../../Aftertrace_01/Assets/Scripts/Enemy/PatrolDrone.cs))

- **Cone sprite size ≠ real detection range.**
  *Cause:* the cone art was decorative under the old system; the new code used a different
  range. Players could be detected slightly outside the visible cone or stand inside a
  visible cone and not be seen.
  *Fix:* regenerated the cone sprite in `EchoArt` to match `viewRange` and the half-angle
  used in `CanSee`. (PR #5)

- **Stealth detection drifted upward when you walked behind cover then back out.**
  *Cause:* I was incrementing the meter every frame in `Update` but the LoS check is in
  `FixedUpdate`. Frames where the drone hadn't physics-stepped saw stale state.
  *Fix:* the drone calls `GameManager.ReportSeen()` from its `FixedUpdate`, and the meter
  integrates in `GameManager.FixedUpdate` using `Time.fixedDeltaTime`. (PR #5,
  [GameManager.cs](../../Aftertrace_01/Assets/Scripts/Management/GameManager.cs))

- **Death respawns felt floaty.**
  *Cause:* `RespawnRoutine` only set the hit-flash alpha — no impact, no shake, just a fade
  and you're back.
  *Fix:* added a 0.09s hit-stop at `Time.timeScale = 0.12f` plus a 0.55-amplitude camera
  shake, both before the existing 0.2s respawn wait. `CameraShake` decays its trauma in
  `Update` on `Time.unscaledTime` / `unscaledDeltaTime`, and the hit-stop waits on an
  unscaled-time loop, so neither freezes with the timescale. (PR #6)

- **Procedural `.wav` files kept showing as "modified" in `git status` after every Build
  All**, even though nothing audible had changed.
  *Cause:* `EchoAudio` used `Random.value` for noise/transients without seeding. The
  *sequence* was different every editor session, so byte content drifted.
  *Fix:* `Random.InitState(82914)` at the top of `GenerateAll`. WAVs are now byte-identical
  on rebuild. (PR #6)

- **`Exo2-Regular SDF.asset` was "modified" after just opening or playing the project — no
  Build All involved.**
  *Cause:* `EchoFont` was producing a **Dynamic** TMP font asset, which adds glyphs to its
  atlas on demand at runtime; the moment any UI text rendered a glyph that wasn't already
  in the atlas, TMP rewrote the `.asset`.
  *Fix (PR #7):* pre-bake the glyph set the UI actually uses (printable ASCII + Latin-1 +
  arrows / em-dash / ellipsis / curly quotes), then force
  `atlasPopulationMode = AtlasPopulationMode.Static`. The next Build All detects an old
  dynamic asset and regenerates it as static. Also re-parented the generated material and
  atlas texture into the asset so reimport doesn't strip them.

- **The Session-1 "polish" TODO list overstated the work.**
  *Cause:* I'd copied the original wishlist without re-checking what was already built.
  *Fix:* added an in-line correction to Session 01 §6 noting which "juice" items were
  already shipped (echo trail, landing dust, hard-landing shake), and trimmed the new work
  to the genuinely-new items (plate particle, death hit-stop + shake, richer audio). (PR #6)

- **Renaming the Unity project folder is not free — internal links break silently.**
  *Cause:* `Echo_Shift_01/` → `Aftertrace_01/` is a git rename, but every Markdown link,
  `.gitattributes` glob, README badge, and `productName` field that mentioned the old name
  by string had to follow.
  *Fix:* swept the repo for `Echo_Shift_01`, `Echo Shift`, and the concept-document filename
  in one pass before committing; verified every link in `README.md`, `Aftertrace_01/README.md`,
  the two DevLog READMEs, and the CHANGELOG resolves. The C# namespace was deliberately left
  untouched (decision §3) so scripts and scenes did not need to be touched. (PR #144)
