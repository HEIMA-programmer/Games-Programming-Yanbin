## 3. Decisions & how my thinking changed

- **Decision:** **scenes are now the source of truth; the builders are retired**, kept
  on disk behind the DANGER menu as blockout generators and design references.
  **Why:** Session 06 made the art hand-authored; this session makes the *layout* hand-
  authored too (entity placement is composition, same argument). What I actually preserve
  by keeping builders runnable is the ability to regenerate a clean blockout — not the
  shipped scene — and that distinction is now explicit in the menu name.
- **Decision:** narrative is a **dialogue box, not wall text**.
  **Why:** the wall panels died with the backdrop purge for a reason — they competed with
  the environment, couldn't sequence, and couldn't block input for the boot moment. A
  bottom-left terminal box matches the fiction (a machine reading its own log), supports
  speakers/portraits for the story I actually want to tell, and **queues** — two writers
  to one channel must never silently overwrite each other (the same failure shape as
  Session 04's platform-carry bug), applied to narrative.
- **Decision:** commit to **384×216**, not the configurator's 640×360 default.
  **Why:** at 640×360 the robot is 48/360 of the screen height — ant-sized; every kit
  preview frames its scenes at roughly this tighter scale. 384×216 integer-scales exactly
  ×5 to 1080p. The cost: less horizontal context, which the new camera clamps + level
  design absorb.
- **Decision:** the echo gate's door **doesn't latch** (`Door.latch = false`).
  **Why:** a latching door teaches "touch the button once"; a held plate teaches the real
  contract — *the echo is a second body that keeps doing the job while you act*. The
  tutorial moment must force the actual mental model.

## 4. Problems hit & how I solved them

- **UI sprite references randomly became `null` after an editor reload** — bit me twice
  (terminal frame, then screen frame + portrait). *Cause:* sprite rects appended to an
  imported sheet by hand all serialise with **FileId 0** ("identifier uniqueness
  violation"), so references to them break on reload. *Fix:* every UI sprite that gets
  referenced moved to a standalone PNG under `Assets/Art/Sprites/UI/`; rule documented in
  `SPRITESHEET_NOTES.md`.
- **The checkpoint showed three flag poles at once.** *Cause:* `checkpoint.png` is a 9×1
  strip of 16-px columns but was sliced 48×48. *Fix:* re-sliced 16×48.
- **Sprites floated above the ground.** *Cause:* the kit's 13-px bottom padding (see §2).
  *Fix:* measured per-prefab visual offsets + the notes file so the rule survives me.
- **The tutorial door could be jumped over.** *Fix:* a collider-only air wall above the
  door frame (invisible, honest about the level's edges).
- **The dialogue frame had a baked-in black margin** that broke the flush 9-slice. *Fix:*
  cropped the sprite (`terminal_frame_black.png`).
- **Timed test runs froze when the editor lost focus.** *Fix:*
  `Application.runInBackground = true` in `AppBootstrap.Init()`.
- **`VictoryScreen` ignored its `narrativeHold` inspector field** (hard-coded 1.4 s).
  *Fix:* uses the field (default 3 s) — found while pacing the L0 ending beat.
