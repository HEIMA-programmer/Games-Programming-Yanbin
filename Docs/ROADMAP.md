# Aftertrace — Roadmap

A five-week module delivered as **four milestones**. This document is the plan (what each
milestone must achieve) and the working agreement (how the project is run on GitHub). The
copy-paste issue/sub-issue text that fills the board lives in [`BACKLOG.md`](BACKLOG.md).

> This is a **planning document** — specs for work to come, not code. Milestones 2–4 describe
> what to build; the implementation happens later, session by session.
>
> **Status:** Milestone 1 is in progress (Week 2). Milestones 2–4 are planned.

## Guiding principles

- **Ambition goes into the game core.** The first two weeks proved the mechanic and stood up a
  full loop; the slice is *thin*, not *finished*. The remaining weeks invest boldly in the four
  things that make it a game worth playing: **new mechanics & puzzle devices, art/visual & audio
  identity, level & puzzle variety, and narrative depth.** Process work (tests, builds, settings)
  is real but is the *minority*, concentrated in M4 — it never becomes a whole milestone.
- **Variety without padding — the "one new rule per sector" model.** Braid gets enormous variety
  from a single time mechanic by giving each world one new twist; *P.B. Winterbottom* builds 50
  levels from one record-yourself verb. Aftertrace should do the same: **grow the echo's verbs and
  add one fresh rule/device per sector**, redesigning existing levels around them — depth and
  variety, not a pile of similar new levels.
- **Pipeline stays procedural and one-click — sprites now ship as a CC0 / royalty-free
  baseline (M2+).** Prefabs, scenes, audio, materials, and tool integration are still
  regenerated by `EchoShift ▸ Build All`. Sprite art switched at M2 from `EchoArt`'s
  pixel-by-pixel generators to a curated 1-Bit pack (CraftPix + Kenney UI + Google Fonts
  OFL) — the generators stay in source as fallback, and everything else (level layouts,
  audio synthesis, prefab wiring, scene assembly, slicing, tinting, frame composition) is
  still 100% code-driven and idempotent. Licensing tracked in [`CREDITS.md`](../Aftertrace_01/CREDITS.md).
- **One issue → one branch → one PR**, documented in [`DevLog/`](DevLog/) with a
  [`CHANGELOG.md`](CHANGELOG.md) entry. **MoSCoW discipline:** Must > Should > Could; cut
  `could-have` first if a week runs short — never the core game work.

## Milestone 2 — Mechanical Depth & Variety (Week 3 · Jun 1–7)

> **Paste into the GitHub milestone description:**
> Grow the echo from "holds a plate / is a decoy" into a real toolkit. Add the verbs that unlock
> new puzzle classes — **ride your echo**, **carry & push objects**, and a small **device pack**
> (lever, timed gate, an echo-blockable beam) — plus a new threat type, then **redesign existing
> puzzles** around them (one new rule per sector, Braid-style). Optionally prototype a signature
> **"Shift"** layer mechanic that earns the game's title. Variety and fun, not more levels.

**Goal.** Triple the expressive range of the core mechanic so the existing sectors feel distinct
and inventive — the single biggest lever on "is it fun?".

**Issues** (full text in `BACKLOG.md` §2):

- **Ride Your Echo** — the clone becomes a standable, one-way platform you can be carried by
  (`feature`, `area: core`, `should-have`).
- **Echo carries & pushes objects** — a pushable crate the player *and* the echo can move; opens
  box-on-plate, stacking, and box-as-step puzzles (`feature`, `area: core`, `should-have`).
- **Puzzle device pack** — a toggle lever, a timed gate, and an echo-blockable energy beam
  (`feature`, `area: levels`, `should-have`).
- **New threat: scanner/turret enemy + environmental hazards** — one new enemy archetype plus
  spikes/crusher-style hazards for danger variety (`feature`, `area: ai`, `should-have`).
- **"Shift" signature mechanic — design spike + prototype** — a phase/layer toggle that recolours
  the puzzle space and pays off the title; spike feasibility before committing
  (`feature`, `area: core`, `should-have`).
- **Puzzle redesign pass** — weave the new toolkit through the existing sectors, one fresh rule
  per sector (`enhancement`, `area: levels`, `should-have`).
- **Mechanic-validation playtest** — a quick check that the new verbs are teachable and
  softlock-free (`playtest`).
- **Session-03 dev log + changelog** (`documentation`).

**Exit criteria.** Ride + carry + at least two new devices work and are wired procedurally; every
existing sector now uses at least one new verb/device; the "Shift" prototype is either committed
or explicitly deferred with notes; a quick playtest confirms no new softlocks.

## Milestone 3 — Art Direction, World & Audio Identity (Week 4 · Jun 8–14)

> **Paste into the GitHub milestone description:**
> Build on the M2 1-Bit visual baseline (CraftPix + Kenney + OFL fonts): add **per-sector
> palette / tint variation**, **animated character frames** (the CraftPix sheets already include
> idle/run/jump), per-sector parallax / lighting mood, a per-sector **audio identity**, and a
> deeper **narrative** carried by the memory fragments. Tilesets, character art, and fonts come
> from M2's external packs — M3 layers tint, animation, mood, and story on top.

**Goal.** Turn the M2 1-Bit baseline (cohesive but uniform across sectors) into a world with
**per-sector identity** — different palette / mood / silhouettes for each area, animated
characters that react to motion, and audio + narrative that tie the visuals to the lab's story.

**Where the leverage is now.** Sprite ART is no longer the bottleneck (CraftPix delivers it).
M3 leverage: (1) **per-sector tint palette** on top of the white CraftPix base (e.g. cold blue
Sector 01 → teal Deep Labs → warm amber Core); (2) **animated `PlayerAnimator`** wired to the
existing 48-frame Char_Robot sheet (idle / run / jump); (3) per-sector parallax backdrop
selection from the 8 `Background_n_details` variants + Tileset_details mix; (4) per-sector
lighting tint (URP 2D lights) and ambient density.

**Issues** (full text in `BACKLOG.md` §2):

- **Art-direction & palette-ramp system** — per-sector palettes + a shared ramp utility; the
  foundation everything else draws from (`art`, `should-have`).
- **Normal-map generation for sprites** — real depth/relief under the existing 2D lights
  (`art`, `should-have`).
- **Character & entity art + animation** — richer player/echo/enemy sprites with squash-&-stretch
  and proper frames (`art`, `should-have`).
- **Environment tilesets & props** — auto-tiled ground/walls + decorative set dressing per sector
  (`art`, `area: levels`, `should-have`).
- **Backgrounds & lighting mood** — layered parallax + per-sector lighting palette and atmosphere
  (`art`, `should-have`).
- **VFX pass** — bring echo/dust/dissolve/plate/death/beam VFX up to the new art bar
  (`polish`, `area: art`).
- **Audio identity** — per-sector music themes + ambient beds + more characterful SFX, still
  procedural (`area: audio`, `should-have`).
- **Narrative & world depth** — a clearer arc, environmental storytelling, lore-bearing fragments,
  a stronger ending (`area: narrative`, `should-have`).
- **Session-04 dev log + changelog** (`documentation`).

**Exit criteria.** Sectors are visually distinct and lit with real depth; sprites/tilesets/
backgrounds all regenerate from the upgraded builders (one-click, original); each sector has its
own musical/ambient feel; the fragments and ending tell a coherent story.

## Milestone 4 — Climax, Polish & Ship (Week 5 · Jun 15–21)

> **Paste into the GitHub milestone description:**
> Land the game. A **climactic finale** that uses the whole toolkit, a **whole-game variety &
> difficulty pass**, a final **game-feel/juice** pass, then the essentials to ship: a minimal
> settings/accessibility set, **Windows + WebGL builds**, a tagged **v1.0.0 release**, a final
> playtest, and the closing documentation. Report and demo video are delivered separately.

**Goal.** A memorable ending and a finished, downloadable, well-documented game.

**Issues** (full text in `BACKLOG.md` §2):

- **Climactic finale** — a capstone sequence ("confront your echoes" / a timed escape) that
  combines ride, carry, devices, stealth, and Shift (`feature`, `area: core`, `should-have`).
- **Whole-game variety & difficulty/pacing pass** — tune the full arc now that every mechanic
  exists; make each sector feel distinct (`enhancement`, `area: levels`).
- **Final game-feel / juice pass** — screenshake with easing + decay, squash-&-stretch, snappier
  transitions, satisfying feedback throughout (`polish`).
- **Essentials: settings + minimal accessibility** — master/music/SFX volume; reduce-motion and
  hold-vs-toggle record options (`feature`, `accessibility`, `should-have`).
- **Windows + WebGL builds (smoke-tested)** (`area: build`).
- **v1.0.0 release** — tag + GitHub Release + builds attached + CHANGELOG 1.0.0 (`area: build`,
  `documentation`).
- **Final playtest + bug fix** (`playtest`).
- **Final docs** — README, credits, Session-05 dev log, retrospective; report + demo tracked here,
  delivered outside the repo (`documentation`).
- **Final triage** — close remaining issues and all four milestones (process).

**Exit criteria.** `v1.0.0` tagged with both builds attached; the finale lands; no known
softlocks; all milestones closed.

## Design references

Grounding for the plan (and useful citations for the report):

- **Braid** — each world introduces *one* new twist on a single time mechanic and escalates;
  time-immune objects create depth. The model for "variety via one new rule per sector."
- **The Misadventures of P.B. Winterbottom** — ~50 puzzles built from one *record-yourself* verb;
  proof that the echo can carry the whole game if its verbs grow.
- **Super Time Force** — recorded "ghosts" act alongside you; co-op-with-your-past-self framing.
- **Celeste** — game-feel benchmark: vertical stretch on jump, sideways squash on land, hair/dust
  follow with delay.
- **Procedural art** — palette-ramp-driven sprites + **normal maps for pixel art** so 2D lights
  give relief; auto-tiling for tileset edges; crisp integer stroke widths.
- **Juice** — screenshake 50–300 ms with an easing curve and decay; short-lived particle bursts;
  "juice should always echo your core gameplay."

## GitHub process & agility — recommendations

Concrete ways to make the *process* visible (the module rewards steady, evidenced development).
Ordered by value-for-effort.

### A. Set up now (cheap, high signal)

1. **A GitHub Projects (v2) board** — columns **Backlog → To Do (this week) → In Progress →
   In Review → Done**. Add the four milestones; drop every issue on the board.
2. **Milestones with due dates** — each then shows a live progress bar (a one-glance burndown).
3. **The label scheme above** — so the board filters by area/priority and your MoSCoW thinking
   shows on every card.
4. **Native sub-issues** — parent = one PR/feature, sub-issues = its tasks; the parent shows
   "x of y complete".
5. **This roadmap + backlog in the repo** (done) — link them from the root README.

### B. Habits per issue / per PR

6. **Branch naming** — keep `feature-*` / `docs-*` / `fix-*`; note it in a short `CONTRIBUTING.md`
   so it reads as a deliberate convention.
7. **`Closes #N` in the PR body** going forward → merging auto-closes and auto-links the issue.
   (For already-merged PRs, link by hand via the issue's **Development** sidebar — see `BACKLOG.md`.)
8. **PR template** — codify the `Summary / What changed / How to test` format you already write
   as `.github/pull_request_template.md`.
9. **Issue templates** — `.github/ISSUE_TEMPLATE/` with `feature.yml`, `bug.yml`, `playtest.yml`.
10. **One dev-log entry + one CHANGELOG bump per session/milestone** — already your rhythm.

### C. Bold / optional

11. **Project board automation** — auto-add new issues; move to **In Review** on linked PR; move
    to **Done** on close. Agility with zero manual dragging.
12. **GitHub Actions — docs link check** — validate Markdown links in `Docs/` on push. No secrets.
13. **GitHub Actions — Unity CI** (`game-ci`) — compile + EditMode tests on push. Impressive for a
    games module, but needs a Unity licence secret; schedule for M4 only if on track.
14. **GitHub Releases** at v1.0 (and optionally per milestone) with build artifacts attached.
15. **README badges** — Unity version, licence, latest release.

> Recommended minimum: **A (all) + B6–B8 + C14**; add C11 if you enjoy it, C13 only if M4 allows.
