# Aftertrace — Game Concept Document

## One-Sentence Game Idea

A 2D puzzle-platformer where the player records their own actions and replays them as a ghost clone to solve cooperation puzzles alone.

---

## Smallest Playable Version (MVP)

One scene, one puzzle, four scripts, all placeholder art:

```
[Start] ——ground—— [Pressure Plate] ——ground—— [Door] ——ground—— [End]
```

The player walks onto the pressure plate, presses R to record, stands for a few seconds, then releases R. A semi-transparent clone appears and replays the recorded action — standing on the plate. The door stays open while the clone holds the plate. The player runs through before the clone disappears.

If this flow works, the core idea is proven.

---

## What the Player Does Moment to Moment

1. **Observe** the room and identify what needs two bodies to solve
2. **Plan** what the clone should do and where to record
3. **Record** by pressing R at the right spot, performing the needed action
4. **Release R** — a ghost clone appears and replays the recorded action
5. **Act** — while the clone is active, run to complete the other half of the task
6. **Solve** the puzzle and enter the next room

This creates a repeating tension–resolution cycle: every room is a small "figure it out, then execute" challenge.

## Unity Technical Plan

### Player Control

| Script                | Purpose                                                                                                                                 |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `PlayerController.cs` | New Input System: WASD movement + Space to jump                                                                                         |
| `EchoRecorder.cs`     | Press R to record player position data into a List each frame; on release, instantiate the echo clone prefab and pass the recorded data |
| `EchoPlayback.cs`     | Reads the position List frame by frame, moves the clone to match, then destroys itself when playback ends                               |

### Game Rules

| Script             | Purpose                                                               |
| ------------------ | --------------------------------------------------------------------- |
| `GameManager.cs`   | Tracks player health, collectible count, and win/lose conditions      |
| `LevelLoader.cs`   | Handles scene transitions: Main Menu ↔ Levels ↔ Victory Screen        |
| `PressurePlate.cs` | Uses OnTriggerStay2D / OnTriggerExit2D to open or close a linked door |

### World Behaviour

| Script                 | Purpose                                                                           |
| ---------------------- | --------------------------------------------------------------------------------- |
| `MovingPlatform.cs`    | Platform moves back and forth along a defined path                                |
| `PatrolEnemy.cs`       | Enemy patrols a path; deals damage on contact with the player                     |
| `MemoryCollectible.cs` | Rotates in place; disappears on trigger contact and updates the collectible count |

### Feedback (UI, Sound, Animation)

| Category      | Implementation                                                                                                                                                           |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **UI**        | `UIManager.cs` manages main menu, HUD, pause screen, and victory/defeat screens using Canvas and UGUI; Canvas Scaler set to Scale With Screen Size for responsive layout |
| **Sound**     | `AudioManager.cs` handles looping BGM and one-shot sound effects (jump, record, collect, death) via AudioSource components                                               |
| **Animation** | Animator state machine for player idle/run/jump transitions; echo clone uses a semi-transparent material with a fade-out effect; doors use simple positional animation   |

## Biggest Risk

**The echo recording and playback system may not feel right.**

Everything else in this project — movement, jumping, UI, menus, scene loading — is standard Unity work covered in class. The one technical unknown is the echo clone. Specific risks:

- **Collision problems:** The clone replays position data directly, so it may clip through walls or ignore physics. If the clone needs to interact with triggers (e.g. standing on a pressure plate), its collider must be active and correctly positioned during playback.
- **Timing mismatch:** If the game runs at an inconsistent frame rate, the replay speed may drift out of sync with what the player expects, making puzzles feel unreliable.
- **"It just doesn't feel fun":** The mechanic might be confusing or tedious rather than satisfying. This can only be discovered by playing it.

**Mitigation:** Build the MVP in Week 1 using only boxes and the four core scripts. Test the pressure plate puzzle immediately. If collision or timing feels wrong, fix it before building any levels. If the mechanic itself is not fun, simplify or adjust the recording rules while scope is still small.

## Scope Sorting (MoSCoW)

### Must Have — Without these, the game does not exist

| Feature                                                  | Why it is essential                                                      |
| -------------------------------------------------------- | ------------------------------------------------------------------------ |
| Player movement and jumping                              | No game without player control                                           |
| Echo record and playback                                 | The entire game idea depends on this one mechanic                        |
| Pressure plate + door interaction                        | The simplest proof that the clone mechanic creates real puzzles          |
| At least one complete level with 3–4 puzzles             | Assessment requires a convincing vertical slice                          |
| Tutorial section teaching controls and the echo mechanic | Players must understand what to do without external help                 |
| Main menu (New Game, Instructions, Exit)                 | Assessment explicitly requires a complete player flow                    |
| HUD showing health and collectible progress              | Assessment requires visible feedback during gameplay                     |
| Victory and defeat screens                               | The game loop must have a clear start and end                            |
| Scene transitions (menu → level → end screen → menu)     | A vertical slice must feel like a complete experience                    |
| Basic sound effects (jump, record, collect, death)       | Assessment lists audio as a required game system                         |
| GitHub repository with steady commits from Week 1        | Assessment: "A last minute upload is not the same as steady development" |

### Should Have — Strongly expected for a high mark, plan to include

| Feature                                                             | Why it matters                                                            |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| A second level introducing a new element (enemy or moving platform) | Shows difficulty scaling and progression, directly supports the report    |
| Patrol enemy with simple back-and-forth AI                          | Assessment values AI "where relevant"; one simple enemy demonstrates this |
| Pause screen with unpause and main menu buttons                     | Covered extensively in class (GP29); assessor will expect it              |
| Responsive UI across aspect ratios (Canvas Scaler + anchors)        | Taught in class (GP30); demonstrates technical competence                 |
| Background music looping per scene                                  | Assessment lists audio; music greatly improves presentation quality       |
| Collectible memory fragments (optional pickups)                     | Adds player motivation and a second layer of engagement                   |
| Proper sprite art replacing placeholder boxes                       | Visual polish matters for the demo and presentation                       |
| Player animation state machine (idle / run / jump)                  | Demonstrates the Animator system taught in class (GP22)                   |
| Credits screen listing all external assets                          | Assessment requires awareness of legal and ethical issues                 |
| Playtest notes documented in the repository                         | Assessment: "evidence of testing and what you changed because of it"      |

### Could Have — Nice extras if time allows in Week 4–5

| Feature                               | Benefit                                                           |
| ------------------------------------- | ----------------------------------------------------------------- |
| A third level combining all mechanics | Stronger vertical slice, but two levels already prove the concept |
| Echo clone fade-out particle effect   | Visual polish; makes the clone feel more alive                    |
| Screen shake on player death          | Small but noticeable feedback improvement                         |
| Moving platforms                      | Adds puzzle variety, but increases level design time              |
| Timer or par-time display per level   | Adds replayability; easy to implement but low priority            |
| Custom cursor or crosshair            | Seen in the class main menu prefab (GP32); minor polish           |
| Key rebinding UI                      | Supports accessibility, but complex for the benefit               |
| Level select screen                   | Only useful if three or more levels exist                         |

### Cut First — Remove immediately if behind schedule

| Feature                                    | Why it can go                                                                            |
| ------------------------------------------ | ---------------------------------------------------------------------------------------- |
| Third level                                | Two levels plus tutorial is already a complete vertical slice                            |
| Moving platforms                           | Pressure plates alone are enough to prove the mechanic                                   |
| Branching narrative or multiple endings    | Linear narrative is simpler and the assessment does not require branching                |
| Online leaderboard or score sharing        | Completely out of scope for this project                                                 |
| Controller / gamepad support               | Keyboard and mouse is sufficient for the demo                                            |
| Multiple echo clones active simultaneously | Dramatically increases complexity for puzzle design and code; one clone is enough        |
| Dialogue system or cutscenes               | A few lines of on-screen text serve the same narrative purpose at a fraction of the cost |
| Procedural level generation                | Handcrafted levels are more polished and easier to test                                  |
